# 底盘控制结构

`application/chassis_task.c` 只负责初始化、控制周期和调用次序。内部模块接收已初始化的非空底盘状态，周期参数以秒为单位；不在每个私有函数重复检查指针。

## 一个周期

```text
采集与估计 → 模式迁移 → 普通目标 → 起立/跳跃覆盖 → 攀爬覆盖
          → PID/LQR + 前馈 → VMC映射 → 自救覆盖时重映射 → 电机发送
```

周期使用实际 RTOS tick 间隔。电机发送中原有的等待和末尾任务延时保留，不能把末尾的 2 ms 延时当作实际控制周期。

## 模块边界

| 文件 | 负责 | 不负责 |
| --- | --- | --- |
| `application/chassis_task.c` | 初始化装配、实测周期、调度 | 传感器解算、目标和力矩公式 |
| `module/chassis_types.h` | 模式、姿态、力矩和电机共享数据类型 | RTOS 任务入口 |
| `application/chassis_config.h` | 硬件换算、控制默认值、在线调参声明 | 周期状态 |
| `module/chassis_observer.c` | 电机/IMU读取、腿部运动学、重力投影、KF接入、速度回退、相对里程 | 操作手指令和目标生成 |
| `service/kalman_service.c` | 两状态 `[速度, 加速度等效零偏]` KF | 接地判定、超时策略、坐标变换 |
| `module/chassis_contact.c` | 支持力估计、接地/离地分类 | 修改控制力矩 |
| `module/chassis_mode.c` | 使能、起立、跳跃迁移及对应腿部目标 | 普通移动、攀爬、自救 |
| `module/chassis_motion.c` | 操作指令解释、普通速度/高度、停车位置和yaw目标接入 | 估计真实位置、VMC、电机发送 |
| `module/chassis_follow.c` | 手动/自动yaw参考算法 | 修改平移、腿长和电机力矩 |
| `module/chassis_climb.c` | 攀爬状态、腿长/速度目标及阶段策略标志 | 清零LQR或映射电机输出 |
| `module/chassis_recovery.c` | 自救状态及虚拟力/力矩覆盖 | 直接发送电机指令 |
| `module/chassis_control.c` | PID/LQR接入、离地控制、前馈、收腿输出策略、VMC及限幅 | 传感器采集、CAN打包 |
| `components/controller/chassis_balance.c` | 姿态参考、LQR分量和质心前馈的数值算法 | 硬件和动作状态机 |
| `components/algorithm/chassis_leg_math.c` | 五连杆FK、雅可比、虚拟力到关节力矩的数学映射 | 状态机和控制周期 |
| `application/motor_cmd.c` | 按使能状态打包并发送电机指令、超电任务 | 求控制目标和控制力矩 |
| `module/chassis_power.c` | 沿用当前速度/yaw参考缩放 | 尚未启用裁判功率闭环或最终电机功率限制 |

在线调参量由使用它的模块持有：跟随参数在 `chassis_motion.c`，PID、姿态、LQR和质心前馈参数在 `chassis_control.c`。原有使用中的标量名与独立 ELF section 保留。

## 停车与云台跟随

- 松杆后先用零速目标制动，位置目标随当前位置更新；融合速度绝对值不超过 `0.06 m/s` 持续 `150 ms` 后，捕获此时的位置。中途超过速度门限重新计时，不再以超时强制锁定滑行中的位置。
- 静止和移动时均可跟随云台，不再要求平移速度超过启动门限。A/D 保留左右行进方向的角度偏置，松开后恢复朝向云台；死区内的平移指令不产生方向偏置。手动转向/自旋指令优先，松开后先减速再恢复自动跟随。
- 自动跟随采用“云台角差 P + 云台绝对转速前馈 → 限速/加减速 → LQR 的 yaw 角速度目标”。前馈由连续底盘 yaw 增量与编码器相对角增量相加后经 `40 ms` 滤波得到，使用 `0.5` 倍；不微分 A/D 方向偏置或对齐零点，手动转向及松杆制动时清零前馈。默认 P 保持 `0.08 (rad/s)/deg`，限速保持 `1.5 rad/s`，加速保持 `4.5 rad/s²`，减速为其 `2` 倍。角差滤波缩短至 `20 ms`，回正或反向时立即收回较大的旧角差。保留 `1°/0.4°` 启停滞回，连续转动的云台需同时满足估计转速低于 `0.04 rad/s` 才退出跟随。
- 转向期间 yaw 角度目标等于实测连续航向，不叠加角度超前或积分角度增量；转速指令归零后捕获航向，由原 LQR 保持。制动包络约束角差修正的相对速度，前馈与修正相加后仍受总转速限制。这些是指令侧约束，不能视为已标定实车停车距离。

## 精简后的约定

- 数值检查留在KF、观测输入和实际限幅边界，私有函数不重复做空指针检查。
- KF无可信轮速时直接返回无效，不再额外预测100 ms，也不自动重新播种。
- IMU/KF无效而落地轮速仍新鲜时，观测模块回退轮速；两者都不可用时暂停积分，位置锁释放，LQR平移误差置零。
- 接地和攀爬模块只报告状态。离地控制与收腿输出屏蔽统一在控制模块执行，防止后续前馈重新叠加。
- 跳跃准备原本恒为真的占位函数已移除，保留原本直接进入伸腿的行为。
- 攀爬中未使用的电流、速度差和腿角基准计算已移除。
- 自救删除了未参与输出的保存腿长，仍采用原有固定0.35 m目标。
- 攀爬撞阶确认后，同周期停止前进并进入平滑收腿，不再经过越阶等待和顶面姿态确认。`CLIMB_PULL_UP` 及后续状态编号保留，便于对照历史波形；撞阶参数、收腿时长和异常中止仍采用当前配置。
- 收腿的双腿到位确认（`10 ms`）与 `300 ms` 收腿轨迹并行，二者完成后直接进入 `CLIMB_STAND_UP`，恢复平衡控制；取消收腿和旧轮子确认阶段串行等待俯仰角速度稳定的流程。旧 `CLIMB_WHEEL_CONFIRM` 编号保留，正常流程不再进入。起立从最后的收腿目标开始，保持腿长目标连续，且必须完成 `500 ms` 起立轨迹后才开始站稳确认，避免 `6 cm` 高度容差使其提前结束。姿态异常中止、收腿未到位超时和再次按 F 平滑退出仍保留；该衔接条件不等于直接测到了轮子接触台阶顶面。

## 验证

```powershell
cmake --build --preset chassis
python tools/chassis/tests/run_control_checks.py
python tools/chassis/tests/run_climb_checks.py
```

主机测试执行生产模块，替换RTOS/传感器接口与CMSIS矩阵运算的宿主实现。覆盖估计、模式、普通运动、接地控制、自救、攀爬和最终VMC输出；不代表实车性能或F407实时耗时。

当前轮速量测仍是左右轮速均值，未增加摆腿/伸缩补偿、IMU杆臂补偿或自动打滑识别；KF噪声参数仍需实车日志标定。
